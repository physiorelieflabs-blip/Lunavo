# 37. LIVE CURRENCY CONVERSION — NO FIXED FIGURES

This requirement applies **everywhere in TS Commerce**.

Never use fixed pre-prepared exchange-rate figures.

Never hard-code:

`1 USD = X NGN`

or any similar permanent rate.

Do not create a static list and pretend it is current.

Whenever currency conversion is required, the system must obtain the **current/recent market exchange rate from a trusted live internet-based source or configured payment/FX provider**.

Examples of where live conversion is required:

* Product prices
* Cart prices
* Checkout
* Customer payments
* Merchant settlement
* Merchant subscription
* Fees
* Taxes where applicable
* Shipping where applicable
* Refunds
* Payouts
* Supplier orders
* Reports
* Platform revenue
* Marketplace transactions

The backend must be authoritative.

---

# 38. LIVE RATE SOURCE

The currency engine should obtain rates from a trusted live source.

For every rate, record:

* Currency pair
* Rate
* Source
* Timestamp

Use a controlled short-lived cache to avoid excessive requests.

The cache must have an explicit TTL.

Do not treat old cached data as live indefinitely.

---

# 39. LIVE RATE FAILURE

If the live rate source is temporarily unavailable:

Do NOT silently pretend an old fixed value is current.

Where platform policy permits, use the most recent valid cached rate, clearly record:

**Rate Status = Stale/Recently Cached**

and preserve:

* Original rate timestamp
* Source
* Cache age

For transactions where a stale rate is unsafe, pause/hold conversion and require a valid current rate.

The objective is not to make an unrealistic claim that every vulnerability in existence has been eliminated.
